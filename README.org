#+TITLE: mongo.el

=mongo.el= is a native MongoDB wire protocol client for Emacs Lisp.

It speaks modern MongoDB =OP_MSG= directly and encodes/decodes BSON in Emacs
Lisp.  It is a command-level driver, not a JavaScript evaluator and not a JDBC
adapter.

* Status

This package is under active development.  It is intended to become the
standalone protocol layer used by Clutch's =mongodb= backend.

Implemented areas include:

- BSON encode/decode for core and compatibility types
- TCP, UNIX-domain socket, TLS, =mongodb://=, and =mongodb+srv://=
- SCRAM-SHA-256, SCRAM-SHA-1, X.509, PLAIN, AWS, and one-step OIDC auth
- OP_MSG command helpers, =moreToCome= unacknowledged writes, cursors,
  getMore, killCursors, and compression (=snappy=, =zlib=, and optional =zstd=
  via =mongo-zstd-program=)
- read preference, read concern, write concern, Stable API, sessions including
  load-balanced session support, retryable reads/writes, transaction helpers,
  and client-level =bulkWrite=
- Single-host, direct, replica-set seed-list, and single-socket load-balanced
  connection paths
- connection pool helpers with =minPoolSize=, =maxPoolSize=,
  =maxIdleTimeMS=, =waitQueueTimeoutMS=, =maxConnecting= accounting, and basic
  generation-based pool clearing via =mongo-pool-clear= / =mongo-pool-ready=,
  including ready/checkout maintenance of =minPoolSize=, load-balanced
  per-=serviceId= clearing, optional interruption of checked-out connections,
  and connection-count accounting;
  =mongo-pool-start-monitor= can run SDAM-style heartbeats for
  non-load-balanced pools that clear unhealthy pools and mark cleared pools
  ready again; load-balanced pools do not open dedicated monitor connections.
  Waiting checkouts are evicted on pool clear with =RetryableError=,
  connection-establishment / initial hello network errors get CMAP backpressure
  labels, command-stage non-timeout network errors clear the pool or matching
  load-balanced =serviceId= generation, =waitQueueTimeoutMS= 0 means no
  checkout deadline, and
  load-balanced wait queue timeouts report checked-out cursor / transaction /
  other operation counts;
  pooled cursor helpers keep the same checked-out connection for the initial
  cursor command, getMore, and killCursors, including load-balanced cursors;
  basic CMAP-style events are exposed via =mongo-pool-event-hook=, including
  sanitized pool addresses, non-default pool-created options, Lisp symbol
  =reason= values, and CMAP string =reason-string= values
- basic command monitoring events via =mongo-command-event-hook=, including
  request id correlation, command duration, OP_MSG document sequence exposure,
  bulkWrite =operation-id= correlation, sensitive command redaction, and
  pooled =driver-connection-id= / load-balanced =serviceId= on command events
- SDAM heartbeat monitoring events via =mongo-sdam-event-hook=, including
  paired =server-heartbeat-started= / =server-heartbeat-succeeded= /
  =server-heartbeat-failed= events, topology/server opening/closed lifecycle
  events, plus =server-description-changed= and
  =topology-description-changed= events for monitored topology state changes
- SDAM topology availability predicates:
  =mongo-topology-description-has-readable-server-p= and
  =mongo-topology-description-has-writable-server-p=

Known incomplete areas include complete SDAM/CMAP/command event and waitQueue
spec-suite parity, client-side field level encryption, and full MongoDB
upstream specification-suite parity.

* Usage

#+begin_src emacs-lisp
(require 'mongo)

(let ((conn (mongo-connect '(:url "mongodb://127.0.0.1:27017/app"))))
  (unwind-protect
      (mongo-find conn "app" "users" '(("active" . t)))
    (mongo-disconnect conn)))
#+end_src

Run arbitrary command documents with =mongo-command=:

#+begin_src emacs-lisp
(mongo-command conn "admin" '(("ping" . 1)))
#+end_src

=mongo-command= is the generic RunCommand surface: it does not inherit
connection-level =readConcern= or =writeConcern=, and it returns =ok:1=
=writeErrors= / =writeConcernError= replies as ordinary response documents.
Include those fields explicitly when using a raw command.  Typed helpers such as
=mongo-find=, =mongo-insert=, =mongo-update=, and =mongo-create-index= keep the
driver helper behavior and apply configured concerns where supported.

Use explicit BSON wrappers when the wire type matters:

#+begin_src emacs-lisp
(mongo-insert conn "app" "events"
              (list (list (cons "_id" (mongo-new-object-id))
                          (cons "createdAt" (mongo-datetime 1704164645678))
                          (cons "counter" (mongo-int64 9223372036854775807)))))
#+end_src

* Module Layout

=mongo.el= remains the public entry point.  Implementation modules are split by
stable protocol responsibility:

- =mongo-bson.el= contains BSON value wrappers, BSON encode/decode, byte
  primitives, checksums, and cryptographic byte helpers.
- =mongo-wire.el= contains OP_MSG, OP_COMPRESSED, legacy OP_REPLY frame
  encoding/decoding, snappy/zlib/zstd wire compression helpers, and responseTo
  validation.  zstd uses the optional =mongo-zstd-program= executable.
- =mongo-params.el= contains URI parsing, SRV DNS resolution, connection
  params normalization, TLS params, credentials, read/write concern, server API,
  and pool option helpers.
- =mongo-auth.el= contains native SCRAM, X.509, PLAIN, MONGODB-AWS, and
  MONGODB-OIDC authentication plus ObjectId/session id byte helpers.
- =mongo.el= assembles the client, including connection-state transport
  send/receive glue, command helpers, server selection, transactions, pooling,
  and lifecycle management.
