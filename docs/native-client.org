#+TITLE: mongodb.el Native Client Guide

* Overview

=mongodb.el= is a native MongoDB protocol client.  It opens sockets to =mongod=
or =mongos=, performs the MongoDB handshake, encodes command documents as BSON,
and sends modern =OP_MSG= frames.

It intentionally does not evaluate MongoDB Shell JavaScript.  Callers provide
MongoDB command documents or use the small helper APIs such as =mongodb-find=,
=mongodb-aggregate=, =mongodb-insert=, =mongodb-update=, =mongodb-delete=, and
=mongodb-bulk-write=.

* Module Layout

=mongodb.el= is the package entry point loaded by =(require 'mongodb)=.
=mongodb-bson.el= owns BSON wrappers, BSON encode/decode, low-level byte
primitives, checksums, and cryptographic byte helpers used by auth and wire
framing.  =mongodb-wire.el= owns OP_MSG, OP_COMPRESSED, legacy OP_REPLY frame
handling, snappy/zlib/zstd wire compression helpers, and responseTo validation;
zstd uses the optional =mongodb-zstd-program= executable.
=mongodb-params.el= owns URI parsing, SRV DNS resolution, connection params
normalization, TLS params, credentials, read/write concern, server API, and
pool option helpers.  =mongodb-auth.el= owns native SCRAM, X.509, PLAIN,
MONGODB-AWS, and MONGODB-OIDC authentication plus ObjectId/session id byte
helpers.  Connection-state transport, command execution, server selection,
sessions, transactions, and pooling are assembled by =mongodb.el=.

Caller UI syntax, MongoDB Shell helper parsing, SQL-to-MQL translation, and SQL
Interface JDBC routing stay outside this repository.

* Protocol Capabilities

The native client currently covers ordinary =mongodb://= connections,
single-host/direct topologies, replica-set seed lists with initial
primary/read-preference selection, =mongodb+srv://= DNS discovery, URL-encoded
UNIX-domain socket paths, TCP, TLS, SOCKS5 proxying, OP_MSG commands,
OP_COMPRESSED replies, zlib, Snappy, and optional zstd wire compression, Stable
API mode, single-socket load-balanced mode, logical sessions, retryable reads/writes,
transactions, command timeouts, read preference/read concern/write concern, and
client-level =bulkWrite=.  Pool helpers enforce =minPoolSize=, =maxPoolSize=,
=maxIdleTimeMS=, =waitQueueTimeoutMS=, and =maxConnecting= accounting on
checkout.  A ready pool is populated until =minPoolSize= is satisfied; checkout
and ready paths also refill the pool after idle/dead connections are pruned.
=mongodb-pool-clear= implements basic generation-based clearing:
available connections are closed immediately, and checked-out connections from
older generations are closed when released.  Clearing pauses the pool until
=mongodb-pool-ready= is called.  Manually opened pools start ready; callers that
want SDAM-style background recovery can opt into =mongodb-pool-start-monitor= for
non-load-balanced pools.  Load-balanced pools do not open dedicated monitor
connections.
Callers may pass non-nil =interrupt-in-use-connections= to =mongodb-pool-clear=
to close affected checked-out connections immediately; the pool-cleared event
then includes =interrupt-in-use-connections=.
Clearing an already paused non-load-balanced pool advances the generation
without emitting a duplicate =connection-pool-cleared= event.
The non-load-balanced pool monitor uses a dedicated monitor connection:
successful heartbeats mark cleared pools ready, while failed heartbeats clear
and pause the pool until a later successful heartbeat recovers it.
Checkout attempts waiting for a connection are evicted when the pool is cleared
and receive a =connection-check-out-failed= event with =reason=
=connection-error= instead of waiting for =waitQueueTimeoutMS=.  Checkout
attempts against a paused or cleared pool signal a retryable
=mongodb-error= with =RetryableError=.  As in the MongoDB connection string
specification, =waitQueueTimeoutMS= 0 means the wait queue has no configured
deadline; callers that need an immediate or shorter bound can pass the optional
=timeout= argument to =mongodb-pool-checkout=.  The optional checkout purpose
argument accepts =cursor=, =transaction=, or =other=; load-balanced wait queue
timeouts include the configured =maxPoolSize= and checked-out counts for those
three categories.
Connection-establishment and initial hello network errors receive the CMAP
backpressure labels =SystemOverloadedError= and =RetryableError=.  Errors that
are known not to indicate server overload, such as SOCKS5 proxy failures,
authentication failures, DNS resolution failures, and certificate / hostname
validation failures, are not labeled this way.
After a checked-out pooled connection fails during command execution, non-timeout
network errors clear the pool generation.  In load-balanced mode, only the
failing connection's =serviceId= generation is cleared and the pool remains
available for other serviceIds.  Command response timeouts do not clear the
pool.  =mongodb-pool-cursor-results= and =mongodb-pool-find= keep one connection
checked out for the initial cursor command, getMore, and killCursors.  This is
required for load-balanced cursors, where getMore must stay on the same socket;
after a load-balanced getMore network error, the helper does not issue
killCursors on the failed pinned connection.
When a load-balanced =serviceId= is supplied to =mongodb-pool-clear=, only
connections for that serviceId are cleared and the pool is not paused.  Basic
CMAP-style lifecycle, checkout, checkin, clear, close, connection-created,
connection-ready, and connection-closed events are exposed through
=mongodb-pool-event-hook= as alists.  Connection events include monotonically
increasing =connection-id= values; pool-created events include non-default
pool options, and URI credentials are not included in event addresses.  Close
events include =reason= values such as =stale=, =idle=, =error=, and
=pool-closed=, and checkout-failed / close events also include CMAP string
=reason-string= values such as =connectionError= and =poolClosed=.  Closing a
pool immediately closes available connections; load-balanced connection-ready
and pool-cleared events include =service-id=, while non-load-balanced events
omit that optional key instead of storing nil.  Any
checked-out connections remain associated with the pool and are closed with
=reason= =pool-closed= when released.  Connection-ready, checked-out, and
checkout-failed events include =duration-ms=.

Basic command monitoring events are exposed through =mongodb-command-event-hook=
as alists with =command-started=, =command-succeeded=, and =command-failed=
types.  Events include the command name, database name, request id, connection
address, and duration for terminal events; load-balanced command events include
=service-id=.  Commands run through =mongodb-pool-command= and pooled cursor
helpers also include the pool's driver-generated =driver-connection-id=.
Started events expose OP_MSG document sequences as command array fields.  Split
=mongodb-bulk-write= command events share an =operation-id=.  Sensitive auth and
user-management command/reply fields are emitted as empty documents; sensitive
server error replies retain only =code=, =codeName=, and =errorLabels=.
Unacknowledged writes use OP_MSG =moreToCome= with =writeConcern= =w:0= and
emit a =command-succeeded= event with =(("ok" . 1))= without waiting for a
server reply; =w:0= with =j:true= remains acknowledged.

SDAM heartbeat monitoring events are exposed through =mongodb-sdam-event-hook=.
=mongodb-monitor-once= emits paired =server-heartbeat-started= and
=server-heartbeat-succeeded= / =server-heartbeat-failed= events for
non-load-balanced monitor heartbeats.  Events include =connection-id=,
=address=, and =awaited=; terminal events also include =duration-ms= and
either =reply= or =failure=.  Load-balanced connections do not run dedicated
monitor heartbeats and therefore do not emit heartbeat events.  Successful
connection setup emits =topology-opening= and =server-opening= before initial
description changes.  Disconnect emits =server-closed= and =topology-closed=,
with =topology-closed= emitted last.  Post-handshake hello refreshes, monitor
error state changes, and disconnect-to-Unknown transitions emit
=server-description-changed= and =topology-description-changed= events when the
SDAM server/topology description changes.  RTT-only and last-update-time-only
refreshes do not emit description-changed events.

Callers that consume topology descriptions can test SDAM availability with
=mongodb-topology-description-has-readable-server-p= and
=mongodb-topology-description-has-writable-server-p=.  The readable predicate
accepts the same read preference values used by command options and applies
read preference mode, tag, and maxStalenessSeconds constraints.

Supported authentication mechanisms are SCRAM-SHA-256, SCRAM-SHA-1,
MONGODB-X509, PLAIN, MONGODB-AWS, and one-step or human-callback
MONGODB-OIDC.  Native auth sends MongoDB commands and SASL payloads directly;
it does not use a JDBC driver, =mongosh=, or JavaScript evaluation.

URI options are validated instead of silently ignored.  Unsupported protocol
features should fail with a clear =mongodb-error= and should be documented here
or in =README.org= when the boundary is user-visible.

* Connections

Basic connection:

#+begin_src emacs-lisp
(setq conn (mongodb-connect '(:host "127.0.0.1"
                            :port 27017
                            :database "app")))
#+end_src

URI connection:

#+begin_src emacs-lisp
(setq conn (mongodb-connect '(:url "mongodb://127.0.0.1:27017/app")))
#+end_src

Replica-set seed list:

#+begin_src emacs-lisp
(mongodb-connect
 '(:url "mongodb://db1.example.test,db2.example.test/app?replicaSet=rs0"))
#+end_src

SRV seed list:

#+begin_src emacs-lisp
(mongodb-connect
 '(:url "mongodb+srv://cluster.example.test/app"))
#+end_src

UNIX-domain socket:

#+begin_src emacs-lisp
(mongodb-connect
 '(:url "mongodb://%2Ftmp%2Fmongodb-27017.sock/app"))
#+end_src

* Command Helpers

=mongodb-command= sends a command document to a database:

#+begin_src emacs-lisp
(mongodb-command conn "admin" '(("listDatabases" . 1)))
#+end_src

This is a generic RunCommand-style helper.  It does not automatically apply
connection-level =readConcern= or =writeConcern= to raw command documents, and
it does not parse =ok:1= =writeErrors= or =writeConcernError= replies into
signals.  Callers that need those fields on raw commands should include them in
the command document explicitly.  Collection and database helpers such as
=mongodb-find=, =mongodb-insert=, =mongodb-update=, =mongodb-aggregate=,
=mongodb-create-index=, and =mongodb-drop-collection= keep driver helper semantics:
they apply configured concerns for supported operations and surface write
errors as =mongodb-error=.

Subscribe to command monitoring events when callers need request-id correlation
or load-balanced service tracking:

#+begin_src emacs-lisp
(let ((mongodb-command-event-hook
       (list (lambda (event)
               (message "MongoDB %s %s request=%s"
                        (alist-get 'type event)
                        (alist-get 'command-name event)
                        (alist-get 'request-id event))))))
  (mongodb-command conn "admin" '(("ping" . 1))))
#+end_src

=mongodb-find= returns all cursor results:

#+begin_src emacs-lisp
(mongodb-find conn "app" "users" '(("active" . t)))
#+end_src

Use =mongodb-pool-find=, or the lower-level =mongodb-pool-cursor-results= helper,
when draining cursor results from a pool:

#+begin_src emacs-lisp
(let ((pool (mongodb-pool-open '(:url "mongodb://127.0.0.1:27017/app"))))
  (unwind-protect
      (mongodb-pool-find pool "app" "users" '(("active" . t)))
    (mongodb-pool-disconnect pool)))
#+end_src

=mongodb-aggregate= accepts a vector pipeline:

#+begin_src emacs-lisp
(mongodb-aggregate
 conn "app" "orders"
 [(("$match" . (("status" . "paid"))))
  (("$group" . (("_id" . "$userId")
                ("revenue" . (("$sum" . "$total"))))))])
#+end_src

Client-level =bulkWrite= sends the MongoDB 8.0 =bulkWrite= command to =admin=:

#+begin_src emacs-lisp
(mongodb-bulk-write
 conn
 '((("insert" . "app.users")
    ("document" . (("name" . "Ann"))))
   (("update" . "app.users")
    ("filter" . (("name" . "Ann")))
    ("updateMods" . (("$set" . (("active" . t)))))
    ("multi" . :false)))))
#+end_src

* BSON Values

Plain Elisp values map to common BSON values.  Use wrappers for explicit wire
types:

- =mongodb-object-id= and =mongodb-new-object-id=
- =mongodb-datetime=
- =mongodb-timestamp=
- =mongodb-int32= and =mongodb-int64=
- =mongodb-decimal128=
- =mongodb-binary= and =mongodb-uuid=
- =mongodb-regex=
- =mongodb-min-key= and =mongodb-max-key=

Public helper APIs for caller adapters include =mongodb-document-value-p=,
=mongodb-document-elements=, =mongodb-byte-string=, =mongodb-bytes-to-hex=,
=mongodb-response-ok-p=, and =mongodb-extended-json-to-bson-value=.  Callers should
not use private =mongodb--*= helpers.

* Transactions

The transaction helpers are:

- =mongodb-start-transaction=
- =mongodb-commit-transaction=
- =mongodb-abort-transaction=
- =mongodb-in-transaction-p=

Transactions require logical session support.  Load-balanced connections always
support sessions, matching MongoDB's load balancer rules, even when hello omits
=logicalSessionTimeoutMinutes=.  Retryable writes are only enabled for selected
servers that support logical sessions, with the same load-balanced exception.
Commands inside a transaction carry =lsid=, =txnNumber=, and =autocommit:
false=.  Commit retries follow MongoDB's retryable commit behavior and expose
error labels through =mongodb-error-has-label-p=.

* Scope Boundaries

This package is the protocol/client layer.  UI concerns such as shell-helper
parsing, result grid rendering, completion, SQL Interface routing, and
non-JDBC SQL translation belong in the caller application.

If SQL support is needed without JDBC, build it as a separate layer that parses
SQL and emits MongoDB commands or aggregation pipelines through public
=mongodb-*= APIs.  Do not add a SQL parser, relational planner, BI Connector /
=mongosqld= client, or SQL query console to =mongodb.el= core.

Current gaps include complete SDAM/CMAP/command event and waitQueue spec-suite
parity, CSFLE, and full MongoDB specification-suite parity.
